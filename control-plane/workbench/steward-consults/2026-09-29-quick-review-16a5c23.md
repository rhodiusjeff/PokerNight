## Findings

### High: Closing A Trial Leaves Its Proposal Claim Permanently Held

planning-publication.py:227 accepts a replacement attempt only when the previous
attempt's last event is withdrawn. Trial closure records trial-request-closed and
retains the claim. The public CLI explicitly refuses trial withdrawal at line 926,
and the underlying withdraw function also accepts only local-mock attempts. Reusing
the closed attempt returns closed-unmerged rather than publishing a new request.

Reproduced with the existing disposable TrialControllerTests fixture: publish, close,
then create replacement-attempt for the same proposal. Creation refuses with
"competing publication attempt requires withdrawal"; calling withdraw refuses with
"live hosted activation unavailable". Thus a user cannot close a trial PR to revise
and republish that proposal using the supported workflow. This also blocks recovery
after the trial target becomes stale and a replacement is needed.

Recommended correction: add an explicit, journaled retirement/reentry operation for
closed unmerged trials, verifying closure and relevant target facts before releasing
the proposal claim. Preserve attempt history and prevent reuse of the retired ID.
Add close-then-new-attempt and interruption/retry regressions; do not equate arbitrary
PR closure with withdrawal of production admission authority.

### Medium: Verification Returns Success For A Closed Unmerged Request

planning-publication.py:557 returns the closed-unmerged result before dispatch checks
whether the requested operation is verify-trial. main therefore prints that result and
returns exit code 0 even though no application occurred. The result does not falsely
say applied-trial, but the dedicated verification command succeeds without verifying
application, making its exit code unsafe as the E2E acceptance gate.

Reproduced through public command dispatch after closing the fixture request:
verify-trial --attempt trial-attempt --confirmed exits 0 with state closed-unmerged.
An open request already fails verification later in run_trial, so closed-unmerged
should also be a failed verification, not a successful terminal-state inspection.

Recommended correction: require an actually merged and verified applied-trial result
for verify-trial success. Keep closed-state reporting on inspect/resume as appropriate.
Add public-CLI checks for open, closed-unmerged and merged verification outcomes.
